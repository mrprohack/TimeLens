# TimeLens 1.6 — UX Smoothness, Speed, Error Handling & Code Hygiene

**Date:** 2026-09-24
**Status:** Implemented
**Scope:** Presentation and resilience only. No schema change, no permission change,
no new tracking behavior. Privacy model (local-only) is unchanged.

## Goals

1. **Smoother UI** — visible state changes animate instead of snapping.
2. **More speed** — remove per-snapshot CPU waste; keep every surface feeling live.
3. **Easier to use** — buttons show busy state, success is confirmed, copy is clearer.
4. **Better error handling** — every UI surface degrades gracefully when the service
   worker is busy, waking up, or restarted.
5. **Verifiable** — `npm run check` (build + 160→~170 tests + validator) stays green;
   new tests cover every resilience behavior.

## Plan

### A. Shared messaging resilience (`src/shared/ui.js`)
- `send()` gains a response timeout (default 10 s, injectable) so no UI can spin forever.
- One automatic retry with a short delay for transient channel errors
  ("Could not establish connection", "receiving end does not exist",
  "message port closed") — the MV3 worker is often just waking up.
- Human-readable mapping: "Extension context invalidated" → "TimeLens was reloaded.
  Close and reopen this window…". Timeouts → "took too long to respond".
- New `setBusy(button, state)` helper: `disabled` + `aria-busy` + `.is-busy` spinner class.

### B. Motion polish (`src/styles/ux-polish-v16.css`, loaded via the theme bridge)
- Register `--summary-progress` / `--budget-progress` as animatable `<angle>` custom
  properties so the popup ring and dashboard budget ring animate smoothly.
- Width transitions on progress bars and trend bars; toast slide-in.
- `.is-busy` inline spinner; `.load-failed` centered retry panel.
- Everything disabled under `prefers-reduced-motion: reduce`.

### C. Popup — live and honest (`src/popup/popup.js|html`)
- 1 s ticker keeps the Focus countdown and summary ring up to date while open;
  auto-refreshes once the countdown reaches zero.
- All actions use `setBusy`; saving a limit confirms with "30 min/day saved ✓".
- Errors use `role="alert"` and clear automatically on the next success.

### D. Side Panel — resilient polling (`src/sidepanel/sidepanel.js`)
- Polling switches from a fixed interval to `setTimeout` chains with exponential
  backoff on failure (15 s → 30 s → 60 s cap); returning to the panel resets backoff.
- Buttons use `setBusy`.

### E. Dashboard — never a dead page (`src/dashboard/dashboard.js|html`)
- Initial-load failure shows a centered retry panel (`#load-failed` / `#load-retry`)
  instead of silently leaving placeholder zeros.
- Later refresh failures keep the last good data and report via toast.
- Toast becomes class/tone-driven (`data-tone="error"`), longer display for errors.
- All dialog submits use `setBusy`; the 30 s focus repaint skips hidden tabs.

### F. Blocked page — safe degradation (`src/blocked/blocked.js|html`)
- If `GET_BLOCK_STATUS` fails, the page still explains the boundary from the URL
  params (safe default: extra-time buttons stay hidden) and offers "Try again".

### G. Background perf (`src/background/service-worker.js`)
- `storageBytesApprox` drops the double `JSON.stringify` + `TextEncoder` pass;
  uses a single stringify length (approximate by contract).

### H. Release hygiene
- Version 1.6.0 in `manifest.json` + `package.json`, CI artifact
  `timelens-1.6.0.zip`, CHANGELOG entry, updated `tests/release.test.js`.

### I. Tests
- `tests/ux-polish-v16.test.js`: unit coverage for `send` retry/timeout/friendly
  mapping and `setBusy`, plus static guarantees for the new markup/CSS/plan hooks.
