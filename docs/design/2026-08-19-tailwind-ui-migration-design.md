# TimeLens Tailwind UI Migration Design

## Purpose

Migrate the TimeLens 1.5 presentation layer from hand-authored page CSS to a locally compiled Tailwind CSS v4 design system while preserving all existing extension behavior, privacy guarantees, schema, permissions, and reference-image visual direction.

## Product goal

TimeLens should feel like the approved light blue/white productivity dashboard reference: a precise desktop sidebar, compact top controls, one strong Today/Time Halo focal point, supporting KPI cards, clear usage analytics, a compact extension popup, a focused Usage History drawer, responsive mobile cards with bottom navigation, and a dark blocked/time-out state.

The UI must remain a real browser-extension product rather than a mockup. Production surfaces may only display metrics derivable from the existing local TimeLens snapshot.

## Architecture

### Styling pipeline

- Use Tailwind CSS v4 and `@tailwindcss/cli` as **development/build dependencies only**.
- Compile a single local stylesheet from `src/styles/tailwind.css` to `src/styles/timelens.css`.
- Runtime pages must reference only local packaged CSS. No Tailwind CDN, remote CSS, remote fonts, runtime CSS generation, or dynamic evaluation.
- `npm run build:css` runs before `check` and before packaging.
- GitHub Actions installs dependencies with `npm ci` before running checks.
- Commit `package-lock.json` for deterministic builds.

### Tailwind source organization

`src/styles/tailwind.css` owns:

1. `@import "tailwindcss"`.
2. Explicit `@source` paths for runtime HTML and JS files so generated/dynamic class use is deterministic.
3. TimeLens `@theme` tokens:
   - Time Blue `#3157FF`
   - Focus Violet `#7455FF`
   - Live Mint `#12B886`
   - Alert Amber `#F59E0B`
   - Ink `#101525`
   - Mist `#F4F7FF`
4. Semantic component classes under `@layer components`, including shared cards, buttons, navigation, KPI surfaces, alerts, pills, history rows, mobile navigation, and dialogs.
5. A small explicit custom-CSS section for the Time Halo, circular/donut geometry, blocked-page atmosphere, and other effects that are clearer as CSS than utilities.
6. `prefers-reduced-motion` behavior that removes decorative entrance animation without hiding information.

### Runtime pages

The following production pages use `../styles/timelens.css` as the primary stylesheet:

- Dashboard
- Popup
- Side Panel
- Blocked page
- Onboarding/options where shared primitives are currently used

Page-specific legacy CSS files are removed from runtime `<link>` tags once equivalent Tailwind component rules exist. They may be deleted after tests prove no runtime page references them.

### HTML and JavaScript boundaries

- Keep existing IDs and `data-*` hooks used by JavaScript and tests.
- Do not change the background worker, core analytics, limits, storage, migration, or enforcement contracts.
- Tailwind classes/component classes may be added to static HTML.
- Dynamic HTML generated by JS should prefer stable semantic component class names included in the Tailwind source layer, avoiding fragile runtime-generated utility strings.

## Visual system

### Dashboard

Desktop:
- Fixed white sidebar with four primary destinations plus secondary Usage History.
- Compact topbar with period pills and Focus action.
- One dominant Today/Total Usage hero with Time Halo.
- Smaller supporting KPI cards for Focus, Sites Visited, and Daily Budget.
- Current website quick-action strip.
- Analytics grid containing Time Breakdown, Top Distracting Sites, Alerts, 7-day trend, and Recent Sessions.
- Tighter elevation and calmer border-radius treatment than the previous generic SaaS pass.

Mobile:
- No fixed sidebar.
- Single-column cards.
- Bottom navigation with `env(safe-area-inset-bottom)` spacing.
- No horizontal overflow and no content hidden behind navigation.

### Popup

- One-screen 360×600 target.
- Header, circular Today summary, current site/limit, Focus/Limit controls, and Open Dashboard CTA.
- Optional secondary lists must not push the CTA below the viewport.

### Usage History

- Right-side drawer on desktop, full-screen on mobile.
- Summary stats, tabs, and recent rows with clear hierarchy.

### Blocked page

- Full dark blue/violet atmosphere.
- Centered lock/time boundary message.
- Safe primary action plus Edit Limits.
- Shared Tailwind tokens may be used, but the dark boundary page must not inherit the light dashboard workspace background.

## Signature element

The Time Halo remains the single memorable visual device. It is a clock-inspired segmented circular indicator used prominently on the Today hero and compactly in the popup. Supporting cards remain quieter so the interface does not become a collection of equally loud dashboard widgets.

## Accessibility

- Keyboard focus remains visible on all interactive controls.
- Primary touch targets remain at least 44 px.
- Reduced motion disables decorative Halo/bar entrance effects.
- Color is not the sole carrier of warnings or state.
- Mobile fixed navigation reserves safe-area content space.

## Runtime and privacy constraints

- Manifest V3 remains unchanged except no change is expected at all for this migration.
- Schema remains v4.
- Permissions remain exactly: `tabs`, `storage`, `idle`, `alarms`, `notifications`, `sidePanel`.
- No host permissions, content scripts, backend, telemetry, cloud sync, cookies, or browsing-history permission.
- No remote runtime code or styles.
- Existing tracking, limits, schedules, categories, Focus behavior, warnings, blocking, imports, diagnostics, and migrations must remain behaviorally unchanged.

## Testing strategy

### Build-contract tests

Add tests proving:
- Tailwind and `@tailwindcss/cli` are local dev dependencies.
- `build:css` uses `npx @tailwindcss/cli` or the package binary locally.
- runtime HTML references `src/styles/timelens.css` and never a CDN.
- package/check scripts build CSS before validation/package creation.
- CI performs `npm ci` before `npm run check`.
- the package includes compiled CSS and excludes development-only Tailwind source/config where appropriate.

### UI regression tests

Preserve all existing tests for:
- four dashboard destinations
- sidebar Usage History wiring
- popup compact composition
- blocked-page safe actions
- mobile navigation
- privacy/permission contracts

Add Tailwind-specific assertions for:
- TimeLens theme tokens
- Time Halo component rules
- responsive safe-area navigation
- reduced-motion behavior
- absence of fake metrics in production UI

### Visual QA

Render deterministic Chromium screenshots after compilation at:
- Dashboard desktop: 1440×1000
- Dashboard mobile: 390×844
- Popup: 360×600
- Usage History: 1440×900
- Blocked page: 1440×900

Compare screenshots to the approved reference and fix clipping, density, hierarchy, overflow, or inconsistent surface styling before final verification.

## Acceptance criteria

The migration is complete when:

1. TimeLens builds all runtime styling from Tailwind v4 locally.
2. No runtime page loads Tailwind or any stylesheet from the network.
3. All existing behavior/regression tests pass.
4. Tailwind build-contract tests pass.
5. Validator confirms approved permissions and no remote/dynamic runtime code.
6. Chrome Web Store ZIP builds successfully and contains the compiled stylesheet.
7. Desktop/mobile/popup/history/blocked screenshots are visually reviewed and corrected.
8. PR #6 is updated with final verification evidence and remains unmerged.
